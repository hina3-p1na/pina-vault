# 顧客信頼フライホイール — 信頼が収益を生む構造

## フライホイールの基本構造

```
価値提供（Value Delivered）
    ↓
期待超過（Expectation Exceeded）
    ↓
信頼蓄積（Trust Built）
    ↓
継続利用（Retention）
    ↓
推奨（Referral / Advocacy）
    ↓
新規獲得コスト低下 + LTV向上
    ↓
再投資余力 → さらに良い価値提供
    ↓（ループ）
```

## なぜこれが「ブランド」なのか
フライホイールが回り続けると、会社名・プロダクト名が「信頼のシグナル」になる。
これがブランド力。広告で作るものではない。

## フライホイールを壊す要因
- **短期売上優先の意思決定**: Churnを増やし、推奨を止める
- **Onboarding失敗**: 最初の価値実感が遅れると離脱する
- **CS vs Sales のGAP**: Salesが過剰に期待値を上げてCSが地獄になる
- **スケール時の品質低下**: 人が増えると一貫性が失われる

## 測定すべきメトリクス
| メトリクス | 何を示すか |
|---|---|
| Time to First Value | Onboardingの質 |
| NPS（顧客推奨度） | 信頼蓄積の度合い |
| Net Revenue Retention | フライホイールの回転速度 |
| CAC / LTV比率 | フライホイールの効率 |
| Expansion Revenue % | 推奨・追加投資の量 |

## 組織設計との接続
- フライホイールを回すためにRevOpsは存在する
- CSはフライホイールの「回転維持装置」
- Sales/GTMは「入口設計」（間違った顧客を入れるとフライホイールが逆回転する）

## 個人仮説
> "最も安いCAC（顧客獲得コスト）は、既存顧客の推奨から来る。これが実現している会社だけが長期で勝てる"
