# GTM = 価値の届け方の設計

## GTMへの関心の出発点
「どうやって売るか」より「誰に何の価値を届けるか、そしてそれが実際に届いているか」

## GTMの失敗パターン（繰り返し観察）
1. **ICP（理想顧客）が曖昧** → 全員に売ろうとして誰にも刺さらない
2. **Value Propositionが内向き** → "何ができるか"を言う、"何が変わるか"を言わない
3. **Sales Motionと顧客購買プロセスのズレ** → プッシュ型で信頼を壊す
4. **Win-Lossを分析しない** → 負けた理由を学習せず同じ失敗を繰り返す

## 良いGTMの構造
```
ICP定義（誰が最も価値を受け取れるか）
    ↓
Value Proposition（その人の文脈で価値を表現）
    ↓
Channel & Motion（価値が最も届きやすい経路）
    ↓
Proof（信頼を下げるリスクを最小化）
    ↓
Onboarding（約束した価値を最速で実感させる）
    ↓
Expansion（価値実感 → 追加投資）
```

## Sales/ISとのインターフェース
- インサイドセールスは「フィルタリング」ではなく「価値の事前確認と期待値整合」をする場
- 良いIS担当は「この人がプロダクトで成功できるか」を見極めている

## 個人仮説
> "Sales VelocityよりValue Velocity（価値が届く速度）を上げる方が長期収益は安定する"
